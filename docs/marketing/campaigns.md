# Approved campaign briefs

Every campaign ends with one primary call to action: run Counterfact's quick
start with an OpenAPI document. Adapt the opening and example to each community;
do not post identical link-only promotion.

Use `utm_campaign=frontend-before-backend-q1`, a specific `utm_source`, one of
`social`, `community`, `referral`, `video`, or `newsletter` as `utm_medium`,
and a stable artifact identifier as `utm_content`.

## Build the screen before the endpoint exists

- Audience: React/Vite developers blocked by an unavailable backend.
- Cornerstone: the verified React/Vite example and guided article.
- Observable proof: OpenAPI input, Counterfact command, browser request, rendered profile, edited typed handler.
- Derivatives: 60–90 second captioned demo, LinkedIn post, developer article, GitHub Discussion.
- Primary metric: activated installations attributed to the campaign period and qualified example opens.

## Test the unhappy path before production

- Audience: frontend and test-automation engineers implementing loading and error states.
- Cornerstone: the verified Playwright success/404/503 journeys.
- Observable proof: the same frontend and HTTP boundary rendering all three deterministic states.
- Derivatives: short demo, error-state checklist, developer article, testing-community contribution.
- Primary metric: Playwright example use plus activated installations during the campaign period.

## When a static mock stops being enough

- Audience: developers comparing OpenAPI mocking tools after static responses become limiting.
- Cornerstone: stateful create/read tutorial plus the comparison page.
- Observable proof: generated response progressing to authored state and explicit failure behavior.
- Derivatives: job-based decision table, short demo, discussion prompt, comparison update.
- Primary metric: comparison-to-quick-start intent and activated installations.
- Guardrail: verify every competitor claim against current official documentation immediately before publication.

## Secondary AI sandbox test

Run one bounded message test only after the frontend campaigns are measurable.
Use the existing agentic-sandbox documentation and compare activated use—not
click volume—with the frontend campaigns. Do not change primary positioning
from this test alone.
