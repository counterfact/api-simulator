# Counterfact case-study expansion protocol

Frozen before additional classification on 2026-09-09. This is a retrospective expansion after inspecting version 3, not preregistration. Audience: engineering practitioners. Question: What shipped, what broke, how did corrections reach users, and what did verification demonstrably catch as agent-assisted development became part of Counterfact?

Observation interval: [2024-09-01T00:00:00Z, 2026-09-04T00:00:00Z). Adoption: 2026-03-10T16:38:20Z. Preserve original matched historical and ninety-day analyses as supporting comparisons. Reconcile the six hours after the original 2026-09-03T18:00:00Z snapshot. Later retrieval, adjudication and experiments are not observation-period events.

Census: paginate public issues and PRs without label-only screening; include bodies, relevant comments, repair merges, releases, direct first-parent changes, and earlier records needed for opening backlog. Preserve normalized public source records, queries, retrieval dates, pagination counts and immutable refs. No credentials. Every screened record receives a disposition and reason. Inaccessible or uncertain evidence remains unresolved. Never infer completeness from a successful request alone.

Count confirmed faulty product behavior once per underlying defect, linking duplicate issues and fixing PRs. Separate external-human, internal-human, automated/agent and unknown discovery channels; authorship alone does not prove discovery. Separate already-released defects, pre-release findings, unknown release status and process incidents. Preserve origin classification separately from chronology confidence; an earliest confirmed affected bound is not an exact origin. Issue closure is not a corrected release. Preserve old population identifiers.

Monthly outputs: non-dependency merges, published releases, confirmed released-defect reports by discovery channel, corrections first publicly released, and known publicly reported defects awaiting correction. Reconstruct identifiable carry-in records, disclose incomplete ascertainment, split March at adoption for pre/post summaries, label September 2026 partial. Date-only evidence cannot support invented exact timestamps. No causal fit, universal quality score, defect/download rate, or defects-prevented estimate.

Mature comparison: releases first affected within intake and externally reported within their individual 90-day follow-up; response records have individual report-based 90-day deadlines and administrative censoring. This is a follow-up and censoring rule for comparable historical evidence, not a repair target or MTTR measure. Derive membership and denominators from records, with errors for unresolved required boundaries rather than invented totals.

Fixed experiment population: issues 1617, 1618, 1619, 1842, 1933, 1971, 2075. Attempt all seven. Use the same assertion on affected and corrected immutable states. Prefer contemporaneous tests; label compatibility adaptations and audit-created reproducers. Packaging cases exercise published artifacts. Outcomes: demonstrated detection, did not distinguish, inconclusive with diagnosed reason. Retain all attempts, commands, runtime versions and relevant output. Environment failure is not behavioral detection. No substituting easier cases and no whole-suite or whole-project inference.

Queries: GitHub REST repository issues (all states, paginated), pulls (all states, paginated), issue comments and PR files where needed; npm registry package publication metadata; local pinned Git first-parent log and diffs. Query-specific parameters, retrieval times, completeness and source hashes belong in source metadata. Unknown backlog and source gaps must be visible in output.
